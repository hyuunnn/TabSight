# 개발과 유지보수

기준: 2026-09-27. [README](../README.md) · [구조](architecture.md) · [알고리즘](algorithms.md)

## 1. 어떻게 만들었는가

연습 화면, 프로젝트 데이터, API, 오디오·영상 처리 연결, 운지 탐색, 편집·저장, GP 출력 연결과 검증 코드는 이 프로젝트에서 구현했다.

신경망이나 악보 엔진을 처음부터 학습·제작한 것은 아니다. 공개 도구의 역할을 분리해 연결했다.

| 구성 | 직접 구현하거나 연결한 부분 | 사용하는 외부 구성 |
|---|---|---|
| 웹 화면 | 원본과 악보 배치, 검토·편집 UI, 재생 제어 | React, Vite, lucide-react |
| 악보 | 프로젝트→GP 변환, 원본 시간 동기화, 편집 반영 | alphaTab, PyGuitarPro |
| 음성 | 전처리, 청크 분할, 이벤트 필터, 작업 진행 관리 | FFmpeg, PyTorch, 공개 GAPS 체크포인트와 추론 코드 |
| 음악 규칙 | 튜닝·카포 비용, 화음 운지 탐색, 주법 후보 | librosa, numpy, scipy의 신호 처리 기능 |
| 저장·서버 | 프로젝트 스키마, API, revision·이력, 오류 처리 | FastAPI, Pydantic, SQLite |

사용자가 GP 파일을 가져오면 자동 채보 파이프라인을 거치지 않고 별도 가져오기 경로에서 `source=score`인 기존 악보로 처리하며, 자동 채보 결과와 구분한다.

## 2. 구현에서 선택한 방식과 이유

- **프로젝트 JSON을 기준으로 저장**: 음표의 원본 초 단위 시각과 미정 운지, 추정 근거를 GP 양자화와 별개로 유지한다. 화면과 파일을 같은 프로젝트에서 생성한다.
- **오디오와 운지 추정을 분리**: GAPS가 찾은 음높이를 유지하면서 기타의 중복 운지 문제를 별도로 풀고, 카포·튜닝을 사용자가 바꿀 수 있게 한다.
- **영상은 재생에만 사용**: 손 검출과 지판 인식으로 운지를 보정해 봤지만 측정에서 정확도를 높이지 못해 제거했다. 근거는 [알고리즘 문서](algorithms.md) 6절에 있다.
- **로컬 실행과 단일 분석 큐**: 한 대의 Mac에서 모델 여러 개를 동시에 실행하지 않도록 분석을 한 번에 하나씩 처리한다. 모델은 서버 프로세스에서 필요할 때 로드한다.
- **GP5를 공통 변환 단계로 사용**: Python에서 GP5를 만든 뒤 같은 결과를 브라우저로 표시하거나 alphaTab의 GP7 exporter로 변환한다.
- **실제 파일을 다시 읽어 검증**: 다운로드 성공 여부와 음표 보존 여부를 나누어 확인한다. 검증된 범위는 [validation.md](validation.md)에 기록했다.

연구 선택 근거와 후속 방향은 [research.md](research.md)를 참고한다.

## 3. 개발 환경 재현

Node.js 22 이상, `uv`, `ffmpeg`가 필요하다. Python 지원 범위는 3.11 이상 3.13 미만이며, 실제 검증 환경은 Python 3.12와 Apple Silicon Mac이다. 패키지의 정확한 고정 버전은 [uv.lock](../uv.lock), [package-lock.json](../package-lock.json)을 기준으로 한다.

저장소 루트에서 의존성을 설치한다.

```sh
uv sync --frozen
npm ci
```

터미널 하나에서 Python API를 실행한다.

```sh
.venv/bin/uvicorn server.app:app --host 127.0.0.1 --port 8787
```

다른 터미널에서는 개발 화면을 실행한다.

```sh
npm run dev
```

개발 화면은 Vite가 출력한 주소, 기본 `http://127.0.0.1:5173`에서 연다. 백엔드 코드를 바꾼 뒤에는 서버를 재시작한다. 현재 명령에는 자동 reload 옵션이 없다.

배포용 화면만 사용할 때는 `npm run build` 후 서버를 실행하거나 [TabSight.command](../TabSight.command)를 더블클릭한다. 실행 스크립트는 이미 8787 서버가 응답하면 브라우저만 연다. **이미 실행 중인 서버가 있으면 스크립트를 다시 열어도 재빌드·재시작되지 않는다.** 최신 코드를 반영하려면 기존 서버 터미널에서 Control-C로 종료한 뒤 다시 실행한다.

모델은 처음 분석할 때 `.data/models/`에 다운로드된다. 추론용 API 키는 필요 없다. YouTube 영상과 모델 다운로드에는 인터넷이 필요하며, 화면의 웹폰트(Google Fonts)도 네트워크를 사용할 수 있다. 앱 전체가 항상 완전 오프라인으로 동작한다고 가정하지 않는다.

## 4. 검증 명령과 전제

```sh
.venv/bin/pytest -q
npm run build
npm run test:e2e
npm run test:playback
```

각 명령의 역할은 다르다.

| 명령 | 확인 범위 | 전제 |
|---|---|---|
| `pytest` | 운지·출력·저장·API 규칙과 회귀 검사 | 의존성 설치. `tests/conftest.py`가 임시 데이터 경로를 사용 |
| `npm run build` | TypeScript 검사와 배포 파일 생성 | Node 의존성 설치 |
| `npm run test:e2e` | Chrome에서 실제 렌더링·재생·편집·다운로드 | 실행 중인 서버와 분석 완료된 YouTube 프로젝트, Chrome |
| `npm run test:playback` | 재생선, 원음·악보음 자동 넘김, 반복 복귀, 확대·모바일 재배치 | 위와 같은 서버·프로젝트·Chrome |

브라우저 검사는 기본적으로 미정 운지가 없는 완료 프로젝트를 골라 복제한다. 미디어는 하드 링크로 공유하고, 편집은 복제 프로젝트에만 적용한 뒤 검사 종료 시 복제본을 삭제한다. `test:e2e`는 마지막 단계에서 연습실 목록의 삭제 버튼으로 복제본을 지운다. 현재 테스트는 실제 영상과 충분한 음표가 있는 프로젝트를 전제로 하므로 빈 `.data/`에서는 바로 실행할 수 없다.

브라우저 검사 환경변수는 다음과 같다.

| 변수 | 기본값 또는 역할 |
|---|---|
| `TABSIGHT_URL` | `http://127.0.0.1:8787` |
| `CHROME_PATH` | `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome` |
| `TABSIGHT_E2E_PROJECT` | 복제할 완료 프로젝트 ID를 지정할 때 사용 |
| `TABSIGHT_DATA_DIR` | 서버·검사 스크립트가 사용할 데이터 폴더. 같은 앱을 검사할 때 동일하게 설정 |

브라우저 결과와 스크린샷은 `test-results/`에 저장된다. 현재의 통과 수는 [검증 기록](validation.md)을 참고한다. 테스트 통과는 전체 곡의 채보 정확도 보증과는 별개다.

## 5. 문제가 생겼을 때 확인할 곳

| 증상 | 먼저 확인할 내용 |
|---|---|
| 주소가 열리지 않음 | 서버 터미널, `http://127.0.0.1:8787/api/health`, 포트 8787 사용 여부 |
| API는 되는데 화면이 없음 | `npm run build`로 `dist/`를 만든 뒤 서버를 재시작했는지 |
| 수정한 화면이 반영되지 않음 | 개발 화면 5173인지 배포 화면 8787인지, 기존 서버가 계속 실행 중인지 |
| 처음 분석이 오래 걸림 | 모델 다운로드 단계인지, 서버 로그에 다운로드 오류가 있는지 |
| GP 다운로드가 거절됨 | 미정 운지, 같은 줄에서 양자화 후 겹치는 onset, 마디 밖 음표, 음높이 불일치 |
| 저장 충돌 메시지 | 프로젝트를 다시 열어 최신 revision을 불러온 뒤 재수정 |
| 앱 종료 후 분석 오류 | 중단 작업은 자동 재개하지 않음. 다시 분석은 기존 편집을 대체할 수 있음 |

API 오류는 화면 메시지와 서버 로그에서 확인한다. 서버 로그를 파일로 자동 수집하는 기능은 없다.

## 6. 알고리즘을 바꿀 때의 연결 지점

코드를 읽는 순서는 `models.py → pipeline.py → music.py → export.py → App.tsx / Score.tsx`가 편하다.

- **오디오 모델 교체**: `transcribe_audio`의 출력인 `Note` 목록과 사용 장치를 유지한다. 원본 기준 초, 실제 MIDI, onset/offset 단위를 확인하고 교체 전후 결과를 같은 입력으로 비교한다.
- **영상 근거 다시 추가**: 제거한 구현(자동 지판 검출·수동 보정·손 위치 비용)은 커밋 `49469bf`에 있다. 그대로 되살리기보다 손가락이 어느 줄을 누르는지 판별하는 모델을 먼저 확보한다. 영상의 프렛은 실제 너트 기준이고 프로젝트 프렛은 카포 기준이며, 개방현은 손가락 위치로 판단할 수 없다. 카포 검출을 추가하려면 설정 선택·구간 변경 경로까지 연결해야 한다.
- **운지 비용 변경**: 동일 음높이 유지, 동시 현 중복, 미정 운지 보존을 확인한다.
- **주법 추가**: Python `Note.technique`, TypeScript 타입·편집 UI, 음높이 계산, GP 효과 매핑을 함께 확인한다. 후보 표시와 사용자 검토 상태도 유지한다.
- **리듬 개선**: 원본 초 단위 시간과 출력 tick을 분리하고, 마디 경계·타이·같은 줄 재발음 테스트를 확인한다. 보기 좋은 표기와 onset 보존을 각각 평가한다.
