# 검증과 한계

검증일: 2026-09-27~10-01 (악보 싱크는 09-28, 아래 "09-30 수정 검증"은 09-30~10-01). Apple Silicon Mac, Python 3.12, PyTorch MPS, Chrome에서 수행했다.

## GP·GP5 파일 검증

내보낸 GP·GP5 파일은 alphaTab의 독립 파서로 다시 읽어 **기타 음표 수와 음높이·줄·프렛의 전체 다중집합**이 내부 초안과 일치하는지 확인했다.

타악 후보는 별도 percussion 트랙으로 저장한다. 리듬은 64분음표 단위로 양자화되고 템포는 정수 BPM으로 저장되므로 파일 길이가 원본과 조금 다를 수 있다. 정확한 원본 시간은 프로젝트 JSON에 보존한다. 같은 줄의 재발음은 이전 음을 끝내며, 너무 가까운 같은 줄 음표를 파일에서 표현할 수 없으면 조용히 누락시키지 않고 보정을 요청한다.

특수 주법 후보가 다른 음의 줄을 차지해 음표가 사라지지 않도록 한다. 기존 운지와 양립하지 않는 하모닉스 후보는 운지를 강제로 이동하지 않고 `Harmonic?` 메모로 남긴다. 자연 하모닉스의 실제 음높이, 타이, 카포별 트랙, percussion 트랙은 별도 테스트로 확인했다. 붙임줄로 나뉜 음의 해머온·풀오프·슬라이드 위치와 다시 가져올 때의 주법, 벤딩 높이도 Python 검사로 확인한다(아래 09-30 수정 검증).

Guitar Pro 데스크톱 프로그램에서 직접 열어 확인한 결과는 아니다. 반복 구조·복수 voice·고급 주법의 원본 악보 전체를 그대로 재현한다고 주장하지 않는다.

- 채보 전 설정 확인은 저장된 5곡의 데이터 복사본과 별도 서버로 Chrome에서 직접 확인했다. 설명에 튜닝이 없는 새 곡 흐름은 위 자동 Chrome 검사에도 들어 있다. 설명에 튜닝이 없는 영상(Osamuraisan)은 튜닝·카포 칸이 비고 두 값을 넣기 전에는 시작할 수 없었다. 설명이 있는 영상은 해당 줄 인용과 함께 채워졌고(Half Step Down, 카포 3·4 두 개, 바리톤 Nashville), 대기 중에도 원본 재생이 됐다. 실제 GAPS로 두 곡을 채보해 확인한 설정이 유지되고 음표 수가 변경 전 분석과 같음을 확인했다. 카포를 일부러 틀리게 넣은 곡에서는 설정을 바꾸지 않고 튜닝 제안만 표시됐다. 다시 분석 시 이전 설정 채우기, 음성 파일 가져오기의 직접 입력 안내도 확인했다.
- 영상 기능이 있던 이전 버전의 프로젝트 5개(데이터 복사본)를 현재 코드로 열어 확인했다. 남아 있는 `vision` 데이터는 무시되고, 나머지 필드와 음표는 그대로 읽히며, GP5 내보내기도 통과했다. 운지를 다시 계산하면 음높이는 유지되고 분석 당시 음성 기준 운지와 일치한다.

브라우저 검사는 분석이 끝난 프로젝트를 복제해서 사용하고 종료 후 복제본만 삭제한다. 결과 보고서와 스크린샷은 `test-results/`에 생성된다.

## 09-30 수정 검증

09-30에 고친 내용을 10-01에 다시 리뷰하고 서브에이전트로 교차 검증해 일부를 되돌리거나 보탰다. 수정 전 코드(`main`)와 수정 뒤 코드를 임시 데이터 폴더에서 비교했다. 응답 시간을 뺀 항목은 `tests/test_workflow.py`의 회귀 검사로 남겼다. 고친 동작을 확인하는 검사는 `main`에서 실패하고 수정 뒤에 통과하며, `main`이 맞게 읽던 설명 표기도 함께 고정했다.

- **해머온·풀오프·슬라이드**: 다른 음의 시작이나 마디선 때문에 붙임줄로 나뉜 4가지 경우(해머온, 풀오프, 슬라이드, 마디선을 넘는 해머온)를 alphaTab으로 다시 읽었다. 수정 전에는 모두 자기 붙임줄로 이어졌고, 수정 뒤에는 모두 다음 음으로 이어졌다. `.gp`로 변환한 파일도 같았다. 나뉘지 않은 음은 전과 같다. 10-01 리뷰에서 이렇게 내보낸 파일을 다시 가져오면 붙임줄이 있는 해머온·슬라이드가 일반 음이 되는 것을 찾았다(`main`에서는 주법이 남았다). 가져오기도 마지막 조각의 주법을 읽도록 고쳐 이제 주법이 유지된다.
- **벤딩**: alphaTab이 만드는 MIDI의 벤딩 값을 봤다. 수정 전에는 25반음을 올리고 붙임줄마다 처음부터 다시 올렸다. 수정 뒤에는 1반음을 올리고 붙임줄 동안 그 높이를 유지했다.
- **하모닉스**: 재계산으로 놓을 자리가 없어진 하모닉스, 이전 코드가 그 상태로 저장한 프로젝트, 인공·탭·핀치 하모닉스나 16·19프렛 자연 하모닉스가 있는 GP 가져오기는 수정 전에 미리보기·저장·내보내기가 모두 422였다. 수정 뒤에는 모두 통과했고, 내보내기는 운지 미정 음이 있으면 그 안내로 거절했다. 3·4·5·7·9·12프렛 자연 하모닉스는 전처럼 하모닉스로 가져온다.
- **검토 표시**: 재계산으로 자리가 바뀐 음과 운지 미정이 된 음은 검토 완료 표시가 지워져 검토할 음에 다시 올라왔다. 카포만 옮겨져 같은 자리를 누르는 음은 표시가 유지됐다. 수정 전에는 모두 검토 완료로 남아 목록에서 빠졌다.
- **가져오기 중 응답**: 변환에 3초 걸리는 것처럼 꾸민 서버로 쟀다. 영상 가져오기와 악보 올리기 동안 다른 요청의 최대 응답 시간이 2.72초에서 0.01초로 줄었다. 이 측정 스크립트는 저장소에 두지 않았고 10-01에는 다시 재지 않았다.
- **설명 읽기**: 09-30에는 `Drop C#`, `half step down`을 붙인 이름, `capo at fret 2` 같은 표기까지 넓게 읽도록 고쳤다. 10-01 리뷰에서 `main`이 맞게 읽던 표기를 틀린 값으로 채우는 것을 찾아 되돌렸다. `E Standard (half step down)`은 E standard로, `Drop D (6th string down a whole step)`은 Drop C로, `Drop D (from E standard)`는 E standard로, `Capo at 1:30 on fret 4`는 카포 1로 읽었다. 그 대신 명백한 오독만 좁게 고쳤다. 튜닝 이름은 단어 전체가 맞을 때만 읽고, `standard` 앞의 대문자 음이름을 반영하며, 글자나 콜론에 붙은 카포 숫자는 버린다. 표기 71개를 `main`, 되돌린 판, 현재 코드로 비교했다. `main`이 맞게 읽고 현재 코드가 틀리게 읽는 표기는 없었다. 현재 코드가 `main`과 다르게 읽는 19개는 모두 의도한 변경이다. 그중 `A standard tuning`만 해석이 갈리는데, A standard로 읽는다.
- **공통 검사**: Python 검사 46개, TypeScript 검사, Vite build는 10-01 수정 뒤에 통과했다.
- **다시 하지 못한 검사**: 브라우저 검사(`test:e2e`, `test:playback`)는 분석한 프로젝트가 있는 서버가 필요해 이번 수정 뒤에는 다시 실행하지 않았다. Guitar Pro 데스크톱 앱에서 열어 보지도 않았다.

## 악보 싱크 검증

사람이 만든 악보와 그 곡의 녹음을 함께 구하지 못해, 앱이 채보한 실제 연주 영상 2곡(곡 A, 곡 B)을 GP5로 내보낸 뒤 **템포를 하나로 고정해** 다시 썼다. 파일의 시간이 연주의 루바토와 템포 변화를 모르는 상태가 되어, 손으로 적은 악보처럼 녹음과 어긋난다. 정답은 각 프로젝트의 마디 시각이다(내보낸 음표가 정확히 그 위치에 있다). 오차는 모든 음 시작 위치에서 잰 값이다.

| 경우 | 오차 중앙값 | 90% | 최대 | 0.1초 이내 |
|---|---|---|---|---|
| 곡 A, 템포 고정 | 32ms | 82ms | 0.16초 | 95% |
| 곡 B(카포 5), 템포 고정 | 36ms | 87ms | 0.45초 | 93% |
| 파일 템포를 0.8배로 적음 | 26ms | 71ms | 0.14초 | 97% |
| 파일 템포를 1.25배로 적음 | 34ms | 79ms | 0.17초 | 95% |
| 편곡 차이 흉내: 음 30% 삭제, 10% 옥타브 이동, 5% 엉뚱한 음 추가 | 38ms / 44ms | 82ms / 103ms | 0.16초 / 0.45초 | 95% / 89% |
| 녹음이 파일보다 2반음 낮음 | 32ms | 82ms | 0.16초 | 95% |
| 녹음 앞에 다른 곡 30초 | 36ms | 83ms | 0.17초 | 96% |
| 5~8마디 반복 기호, 녹음에서도 두 번 연주 | 36ms | 81ms | 0.14초 | — |

- 앞 두 줄 외에는 곡 A로 쟀고, 편곡 차이 줄은 곡 A / 곡 B의 값을 함께 적었다.
- 2반음 낮은 녹음에서는 반음 이동 −2를, 30초를 덧붙인 녹음에서는 악보 시작을 32.6초로 찾았다. 반복 구간의 두 번째 연주는 중앙값 47ms, 최대 0.10초였다.
- GP7(`.gp`)로 변환한 같은 악보는 타임라인이 같았고 오차도 같았다.
- 다른 곡의 악보를 맞춘 2개 조합은 모두 "잘 맞지 않음"(`reliable=false`)으로 판정했다. 위 표의 맞는 조합은 모두 믿을 만함으로 판정했다.
- 곡당 계산 시간은 Apple Silicon에서 약 3~5초다.

연주가 악보보다 길어지는 경우는 곡 A의 녹음에서 40마디 근처를 편집해 확인했다.

| 녹음 편집 | 결과 |
|---|---|
| 40~44마디를 1.5배 느리게 | 따라감. 오차 중앙값 33ms, 그 구간 최대 0.94초 |
| 40마디 앞에 악보에 없는 연주 5초 | 나머지는 중앙값 31ms. 끼어들기 직전의 음 5개가 끼어든 동안 늦게 표시됨(최대 5.1초) |
| 같은 방식으로 15초 | 위와 같고, "잘 맞지 않음"으로 잘못 판정 |
| 40마디 앞에서 3초 멈춤 | 멈춘 동안 다음 음 6개가 미리 표시됨(최대 2.3초) |

같은 음을 느리게·길게 친 구간은 맞춘다. 악보에 없는 연주나 멈춤은 그 부분이 끝나면 다시 맞지만, 그동안 앞뒤 몇 음의 위치가 끼어든 길이만큼 어긋난다.

화면과 API는 임시 데이터 폴더와 별도 서버로 확인했다(검사 스크립트는 저장소에 두지 않았다).

- API 16개 항목: 형식이 다르거나 읽을 수 없는 파일 거절과 파일 정리, 올리기 후 싱크 완료, 파일 정보·튜닝 기록, 신뢰도 기록, AI 채보 데이터 없음, 고정점 증가, 목록의 싱크 표시, 원본 파일 그대로 제공, 편집 저장과 튜닝·카포 재계산 거절, 완료 후 다시 올리기 거절, 확인 단계로 돌아가기와 파일 튜닝 채우기.
- Chrome 9개 항목: 확인 화면에서 올리기와 진행 화면, 편집 패널 없는 싱크 화면, 영상 30·75·120·170초와 재생 중에 커서 마디가 정답 마디와 일치, 악보 클릭 시 그 위치로 영상 이동, 악보음 재생 시 영상이 따라옴, 원본 악보 내려받기가 올린 파일과 같음, 악보 바꾸기, 반복 마디 클릭이 현재 위치에 가까운 연주 회차로 이동, 브라우저 예외 없음.

이 결과는 녹음에서 채보한 음을 그대로 쓴 악보라 실제 손 악보보다 녹음과 가깝다. 편곡 차이는 무작위로 흉내 냈을 뿐이다. 사람이 만든 악보는 정답 시각이 없어 오차를 재지 못했다. 사람이 만든 GP7 악보 1곡으로 싱크했을 때는 "믿을 만함"(contrast 0.21, match 0.28)으로 판정됐다.

## 남아 있는 품질 한계

**운지는 소리와 연주 가능성 규칙으로 추정한 값이다.** 같은 음높이를 여러 자리에서 낼 수 있어 연주자가 실제로 친 자리와 다를 수 있다. 영상의 손 위치로 이를 보정하던 기능은 측정에서 정확도를 높이지 못해 제거했다([알고리즘](algorithms.md) 6절). 튜닝·카포는 설명에서 읽거나 사용자가 채보 전에 입력한 값이며, 설명은 `Tuning:` 형식의 줄만 읽는다. 카포 변화와 변칙 튜닝을 소리나 영상으로 판별하지 못한다. 초기 박자는 4/4이며 음악적인 음가 정리가 필요하다. 특수 주법은 학습된 전문 분류기가 아닌 후보 규칙이다. 현재 결과는 손으로 다듬어 연습할 초안이고, 전체 악보 정확도나 수정 소요 시간을 보장하지 않는다.

**악보 싱크는 음이름 흐름으로 맞춘 자동 결과다.** 같은 화음이 오래 이어지거나 한 음을 길게 끄는 구간 안에서는 위치가 조금 밀릴 수 있고, 연주가 반복을 더 하거나 빼는 등 악보와 구조가 다르면 그 근처가 틀어진다. 악보에 없는 연주가 끼거나 연주가 멈추면 그동안 커서가 앞 음에 늦게 머물거나 다음 음으로 미리 넘어가며, 길게 끼면 "잘 맞지 않음"이 잘못 뜰 수 있다. 첫 기타 트랙만 표시·비교하며, 자동 결과를 손으로 고치는 기능은 없다. 악보음은 파일의 템포로 연주하므로 연주자의 빠르기와 다를 수 있다. "잘 맞지 않음" 판정 기준은 위의 몇 가지 조합으로 정한 값이다.
