# 검증과 한계

검증일: 2026-09-27~28 (악보 싱크는 09-28). Apple Silicon Mac, Python 3.12, PyTorch MPS, Chrome에서 수행했다.

## GP·GP5 파일 검증

내보낸 GP·GP5 파일은 alphaTab의 독립 파서로 다시 읽어 **기타 음표 수와 음높이·줄·프렛의 전체 다중집합**이 내부 초안과 일치하는지 확인했다.

타악 후보는 별도 percussion 트랙으로 저장한다. 리듬은 64분음표 단위로 양자화되고 템포는 정수 BPM으로 저장되므로 파일 길이가 원본과 조금 다를 수 있다. 정확한 원본 시간은 프로젝트 JSON에 보존한다. 같은 줄의 재발음은 이전 음을 끝내며, 너무 가까운 같은 줄 음표를 파일에서 표현할 수 없으면 조용히 누락시키지 않고 보정을 요청한다.

특수 주법 후보가 다른 음의 줄을 차지해 음표가 사라지지 않도록 한다. 기존 운지와 양립하지 않는 하모닉스 후보는 운지를 강제로 이동하지 않고 `Harmonic?` 메모로 남긴다. 자연 하모닉스의 실제 음높이, 타이, 카포별 트랙, percussion 트랙은 별도 테스트로 확인했다.

Guitar Pro 데스크톱 프로그램에서 직접 열어 확인한 결과는 아니다. 반복 구조·복수 voice·고급 주법의 원본 악보 전체를 그대로 재현한다고 주장하지 않는다.

## 기능 검사

- Python 검사 **23개 통과**: 음높이 유지, 동시 현 중복 방지, GP/GP5 재읽기, 타이·재발음, 자연 하모닉스 음높이, 카포/타악 트랙, 미정·충돌 음표 차단, 저장 충돌, 실패 시 원본 유지, URL 검사, 취소, 기존 악보 표시, 설명·음역 충돌 시 튜닝 제안, 프로젝트 삭제와 분석 중 삭제 거절, 설명의 음이름 튜닝·Nashville·다른 줄의 카포 읽기, 목록에 없는 설명 튜닝을 비교 후보에 유지, 설정 확인 전에는 채보하지 않고 튜닝만 있는 설명은 카포 0으로 채워 확인한 값 그대로 사용, 튜닝·카포 변경 시 원인 안내와 운지 미정 유지, 하모닉스 자리가 없어진 음의 일반 음 배치.
- 실제 Chrome 검사 **18개 통과**: 홈·실제 악보 표시, 악보 클릭 탐색, 원본 재생/배속, A–B 반복, 합성음, 수정/저장/되돌리기/다시 실행, 추가·삭제, 카포·튜닝 보정, 마디 템포, 새로고침 복원, 오선보 전환, GP5/GP 다운로드·재읽기, 모바일 레이아웃, 연습실 목록에서 삭제, 새 곡의 채보 전 튜닝·카포 확인(입력 전 시작 차단, 대기 중 원본 재생, 입력한 설정으로 짧은 실제 채보), 브라우저 예외 없음. 악보 싱크를 추가한 서버에서 다시 실행해 모두 통과했다.
- 재생 표시 Chrome 검사(`npm run test:playback`) **8개 통과**: 실제 화면 픽셀 기준 재생선 너비, 먼 위치 탐색, 원음·악보음 재생 중 다음 줄 이동, 자동 넘김 해제와 위치 복귀, A–B 반복 시 이전 줄 복귀, 확대·오선보 전환 후 위치 유지, 모바일 한 마디 배치와 가로 넘침. 악보 싱크를 추가한 서버에서도 통과했다.
- TypeScript 검사와 Vite production build 통과.
- 새 YouTube 곡은 실제 링크로 Chrome에서 확인했다. 내려받는 동안 원본 영상 칸에는 준비 중 안내가 보이고 영상을 요청하지 않으며, 설정 확인 화면으로 넘어가면 새로고침 없이 영상과 미리보기가 나오고 재생된다.
- 악보 클릭은 원음 모드에서 빈 곳, 숫자 옆, 앞 마디에서 이어지는 붙임줄, 숫자, 재생 중 클릭을, 악보음 모드에서 빈 곳과 숫자 클릭을 Chrome에서 직접 확인했다. 매번 영상·재생 바·악보 커서가 같은 마디를 가리켰고 숫자를 누르면 음표가 선택됐다. 확인한 경우 중에는 원음 모드에서 누른 채 앞쪽으로 끌어 구간을 선택할 때만 커서와 영상이 다른 박을 가리켰다([구조](architecture.md) 6절). 자동 Chrome 검사는 숫자 클릭만 확인한다.
- 채보 전 설정 확인은 저장된 5곡의 데이터 복사본과 별도 서버로 Chrome에서 직접 확인했다. 설명에 튜닝이 없는 새 곡 흐름은 위 자동 Chrome 검사에도 들어 있다. 설명에 튜닝이 없는 영상(Osamuraisan)은 튜닝·카포 칸이 비고 두 값을 넣기 전에는 시작할 수 없었다. 설명이 있는 영상은 해당 줄 인용과 함께 채워졌고(Half Step Down, 카포 3·4 두 개, 바리톤 Nashville), 대기 중에도 원본 재생이 됐다. 실제 GAPS로 두 곡을 채보해 확인한 설정이 유지되고 음표 수가 변경 전 분석과 같음을 확인했다. 카포를 일부러 틀리게 넣은 곡에서는 설정을 바꾸지 않고 튜닝 제안만 표시됐다. 다시 분석 시 이전 설정 채우기, 음성 파일 가져오기의 직접 입력 안내도 확인했다.
- 영상 기능이 있던 이전 버전의 프로젝트 5개(데이터 복사본)를 현재 코드로 열어 확인했다. 남아 있는 `vision` 데이터는 무시되고, 나머지 필드와 음표는 그대로 읽히며, GP5 내보내기도 통과했다. 운지를 다시 계산하면 음높이는 유지되고 분석 당시 음성 기준 운지와 일치한다.

브라우저 검사는 분석이 끝난 프로젝트를 복제해서 사용하고 종료 후 복제본만 삭제한다. 결과 보고서와 스크린샷은 `test-results/`에 생성된다.

## 악보 싱크 검증

사람이 만든 악보와 그 곡의 녹음을 함께 구하지 못해, 앱이 채보한 실제 연주 영상 2곡(곡 A, 곡 B)을 GP5로 내보낸 뒤 **템포를 하나로 고정해** 다시 썼다. 파일의 시간이 연주의 루바토와 템포 변화를 모르는 상태가 되어, 손으로 적은 악보처럼 녹음과 어긋난다. 정답은 각 프로젝트의 마디 시각이다(내보낸 음표가 정확히 그 위치에 있다). 오차는 모든 음 시작 위치에서 잰 값이다.

| 경우 | 오차 중앙값 | 90% | 최대 | 0.1초 이내 |
|---|---|---|---|---|
| 곡 A, 템포 고정 | 32ms | 82ms | 0.16초 | 95% |
| 곡 B(카포 5), 템포 고정 | 36ms | 87ms | 0.45초 | 93% |
| 파일 템포를 0.8배로 적음 | 26ms | 71ms | 0.14초 | 97% |
| 파일 템포를 1.25배로 적음 | 34ms | 79ms | 0.17초 | 95% |
| 편곡 차이 흉내: 음 30% 삭제, 10% 옥타브 이동, 5% 엉뚱한 음 추가 | 38ms / 44ms | 82ms / 103ms | 0.16초 / 0.45초 | 95% / 89% |
| 녹음이 파일보다 2반음 낮음 | 32ms | 82ms | 0.16초 | 95% |
| 녹음 앞에 다른 곡 30초 | 36ms | 83ms | 0.17초 | 96% |
| 5~8마디 반복 기호, 녹음에서도 두 번 연주 | 36ms | 81ms | 0.14초 | — |

- 앞 두 줄 외에는 곡 A로 쟀고, 편곡 차이 줄은 곡 A / 곡 B의 값을 함께 적었다.
- 2반음 낮은 녹음에서는 반음 이동 −2를, 30초를 덧붙인 녹음에서는 악보 시작을 32.6초로 찾았다. 반복 구간의 두 번째 연주는 중앙값 47ms, 최대 0.10초였다.
- GP7(`.gp`)로 변환한 같은 악보는 타임라인이 같았고 오차도 같았다.
- 다른 곡의 악보를 맞춘 2개 조합은 모두 "잘 맞지 않음"(`reliable=false`)으로 판정했다. 맞는 조합은 모두 믿을 만함으로 판정했다.
- 곡당 계산 시간은 Apple Silicon에서 약 3~5초다.

화면과 API는 임시 데이터 폴더와 별도 서버로 확인했다(검사 스크립트는 저장소에 두지 않았다).

- API 16개 항목: 형식이 다르거나 읽을 수 없는 파일 거절과 파일 정리, 올리기 후 싱크 완료, 파일 정보·튜닝 기록, 신뢰도 기록, AI 채보 데이터 없음, 고정점 증가, 목록의 싱크 표시, 원본 파일 그대로 제공, 편집 저장과 튜닝·카포 재계산 거절, 완료 후 다시 올리기 거절, 확인 단계로 돌아가기와 파일 튜닝 채우기.
- Chrome 9개 항목: 확인 화면에서 올리기와 진행 화면, 편집 패널 없는 싱크 화면, 영상 30·75·120·170초와 재생 중에 커서 마디가 정답 마디와 일치, 악보 클릭 시 그 위치로 영상 이동, 악보음 재생 시 영상이 따라옴, 원본 악보 내려받기가 올린 파일과 같음, 악보 바꾸기, 반복 마디 클릭이 현재 위치에 가까운 연주 회차로 이동, 브라우저 예외 없음.

이 결과는 녹음에서 채보한 음을 그대로 쓴 악보라 실제 손 악보보다 녹음과 가깝다. 편곡 차이는 무작위로 흉내 냈을 뿐이다. 사람이 만든 악보로 잰 결과는 아직 없다.

## 남아 있는 품질 한계

**운지는 소리와 연주 가능성 규칙으로 추정한 값이다.** 같은 음높이를 여러 자리에서 낼 수 있어 연주자가 실제로 친 자리와 다를 수 있다. 영상의 손 위치로 이를 보정하던 기능은 측정에서 정확도를 높이지 못해 제거했다([알고리즘](algorithms.md) 6절). 튜닝·카포는 설명에서 읽거나 사용자가 채보 전에 입력한 값이며, 설명은 `Tuning:` 형식의 줄만 읽는다. 카포 변화와 변칙 튜닝을 소리나 영상으로 판별하지 못한다. 초기 박자는 4/4이며 음악적인 음가 정리가 필요하다. 특수 주법은 학습된 전문 분류기가 아닌 후보 규칙이다. 현재 결과는 손으로 다듬어 연습할 초안이고, 전체 악보 정확도나 수정 소요 시간을 보장하지 않는다.

**악보 싱크는 음이름 흐름으로 맞춘 자동 결과다.** 같은 화음이 오래 이어지거나 한 음을 길게 끄는 구간 안에서는 위치가 조금 밀릴 수 있고, 연주가 반복을 더 하거나 빼는 등 악보와 구조가 다르면 그 근처가 틀어진다. 첫 기타 트랙만 표시·비교하며, 자동 결과를 손으로 고치는 기능은 없다. 악보음은 파일의 템포로 연주하므로 연주자의 빠르기와 다를 수 있다. "잘 맞지 않음" 판정 기준은 위의 몇 가지 조합으로 정한 값이다.
