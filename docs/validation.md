# 검증과 한계

검증일: 2026-09-27. Apple Silicon Mac, Python 3.12, PyTorch MPS, Chrome에서 수행했다.

## GP·GP5 파일 검증

내보낸 GP·GP5 파일은 alphaTab의 독립 파서로 다시 읽어 **기타 음표 수와 음높이·줄·프렛의 전체 다중집합**이 내부 초안과 일치하는지 확인했다.

타악 후보는 별도 percussion 트랙으로 저장한다. 리듬은 박마다 가장 단순한 음가(셋잇단 포함)로 맞추고, 같은 줄의 두 음이 한 자리에 겹치는 박만 64분음표 단위로 적는다. 템포는 마디마다 정수 BPM으로 저장되므로 파일 길이가 원본과 조금 다를 수 있다. 정확한 원본 시간은 프로젝트 JSON에 보존한다. 같은 줄의 재발음은 이전 음을 끝내며, 너무 가까운 같은 줄 음표를 파일에서 표현할 수 없으면 조용히 누락시키지 않고 보정을 요청한다.

특수 주법 후보가 다른 음의 줄을 차지해 음표가 사라지지 않도록 한다. 기존 운지와 양립하지 않는 하모닉스 후보는 운지를 강제로 이동하지 않고 `Harmonic?` 메모로 남긴다. 자연 하모닉스의 실제 음높이, 타이, 카포별 트랙, percussion 트랙, 셋잇단, 베이스·멜로디 두 성부는 별도 테스트로 확인했다.

Guitar Pro 데스크톱 프로그램에서 직접 열어 확인한 결과는 아니다. 성부는 베이스·멜로디 두 개까지만 쓰며, 반복 구조·고급 주법의 원본 악보 전체를 그대로 재현한다고 주장하지 않는다.

## 기능 검사

- Python 검사 **29개 통과**: 음높이 유지, 동시 현 중복 방지, GP/GP5 재읽기, 타이·재발음, 자연 하모닉스 음높이, 카포/타악 트랙, 미정·충돌 음표 차단, 저장 충돌, 실패 시 원본 유지, URL 검사, 취소, 기존 악보 표시, 설명·음역 충돌 시 튜닝 제안, 프로젝트 삭제와 분석 중 삭제 거절, 설명의 음이름 튜닝·Nashville·다른 줄의 카포 읽기, 목록에 없는 설명 튜닝을 비교 후보에 유지, 설정 확인 전에는 채보하지 않고 튜닝만 있는 설명은 카포 0으로 채워 확인한 값 그대로 사용, 튜닝·카포 변경 시 원인 안내와 운지 미정 유지, 하모닉스 자리가 없어진 음의 일반 음 배치, 추적한 비트를 따르는 마디(못갖춘마디·3/4), 편집한 마디의 균등 박, 셋잇단 기록, 베이스의 두 번째 성부(GP5·GP7 재읽기), 같은 줄의 빠른 두 음을 겹치지 않게 기록, 셋잇단과 일반 박이 이어져도 마디 길이 유지.
- 실제 Chrome 검사 **18개 통과**: 홈·실제 악보 표시, 악보 클릭 탐색, 원본 재생/배속, A–B 반복, 합성음, 수정/저장/되돌리기/다시 실행, 추가·삭제, 카포·튜닝 보정, 마디 템포, 새로고침 복원, 오선보 전환, GP5/GP 다운로드·재읽기, 모바일 레이아웃, 연습실 목록에서 삭제, 새 곡의 채보 전 튜닝·카포 확인(입력 전 시작 차단, 대기 중 원본 재생, 입력한 설정으로 짧은 실제 채보), 브라우저 예외 없음. 음표 수정 단계는 편집기가 클릭한 음을 불러온 뒤 값을 읽는다. 편집기는 선택한 음을 렌더링 뒤 effect에서 불러오므로, 이전에는 먼저 선택된 음과 프렛이 같을 때만 통과했다.
- 재생 표시 Chrome 검사(`npm run test:playback`) **8개 통과**: 실제 화면 픽셀 기준 재생선 너비, 먼 위치 탐색, 원음·악보음 재생 중 다음 줄 이동, 자동 넘김 해제와 위치 복귀, A–B 반복 시 이전 줄 복귀, 확대·오선보 전환 후 위치 유지, 모바일 한 마디 배치와 가로 넘침.
- TypeScript 검사와 Vite production build 통과.
- 채보 전 설정 확인은 저장된 5곡의 데이터 복사본과 별도 서버로 Chrome에서 직접 확인했다. 설명에 튜닝이 없는 새 곡 흐름은 위 자동 Chrome 검사에도 들어 있다. 설명에 튜닝이 없는 영상(Osamuraisan)은 튜닝·카포 칸이 비고 두 값을 넣기 전에는 시작할 수 없었다. 설명이 있는 영상은 해당 줄 인용과 함께 채워졌고(Half Step Down, 카포 3·4 두 개, 바리톤 Nashville), 대기 중에도 원본 재생이 됐다. 실제 GAPS로 두 곡을 채보해 확인한 설정이 유지되고 음표 수가 변경 전 분석과 같음을 확인했다. 카포를 일부러 틀리게 넣은 곡에서는 설정을 바꾸지 않고 튜닝 제안만 표시됐다. 다시 분석 시 이전 설정 채우기, 음성 파일 가져오기의 직접 입력 안내도 확인했다.
- 영상 기능이 있던 이전 버전의 프로젝트 5개(데이터 복사본)를 현재 코드로 열어 확인했다. 남아 있는 `vision` 데이터는 무시되고, 나머지 필드와 음표는 그대로 읽히며, GP5 내보내기도 통과했다. 운지를 다시 계산하면 음높이는 유지되고 분석 당시 음성 기준 운지와 일치한다.

브라우저 검사는 분석이 끝난 프로젝트를 복제해서 사용하고 종료 후 복제본만 삭제한다. 결과 보고서와 스크린샷은 `test-results/`에 생성된다. 이번 변경의 브라우저 검사는 데이터 복사본(미디어는 하드 링크)과 별도 포트의 서버로 실행했다.

## 레퍼런스 악보 평가

[scripts/evaluate.py](../scripts/evaluate.py)로 GP 악보 22곡(정성하 15곡, Masaaki Kishibe 7곡)을 각 연주자가 YouTube에 올린 해당 연주와 짝지어 측정했다. 악보 23개 중 Iris Out은 악보가 영상의 연주와 맞지 않아 뺐다. 악보와 음원은 저장소에 넣지 않고 `.data/eval/`에 둔다.

- **정렬**: 악보를 반복 기호대로 펼쳐 연주 순서로 읽는다([reference-tab.mjs](../scripts/reference-tab.mjs)). 합성한 악보와 녹음을 크로마 DTW로 맞추고, GAPS가 찾은 같은 음높이의 onset으로 시간을 다시 보정한다. 확인한 곡에서 짝지은 음의 onset 차이는 사분위 범위 5~7ms였다.
- **음표 F1**: 같은 음높이, onset ±50ms.
- **줄 정확도(악보 음)**: 악보의 음표·튜닝·카포를 그대로 넣었을 때 악보와 같은 줄을 고른 비율. 채보 오류를 뺀 운지만의 값이다.
- **줄 정확도(GAPS 음)**: 악보와 짝지은 GAPS 음표 중 줄이 같은 비율.
- **비트·첫 박 F1**: ±70ms. 박자표는 마디당 박 수로 비교했다(6/8은 2박).
- **악보와 같은 박 안 위치**: 추정한 박이 악보의 박과 맞는 곳에서, 파일에 적힌 음이 악보와 같은 박 안 위치(셋잇단 포함)에 있는 비율.

실제 내보내기(미리보기 아님)는 두 버전 모두 18곡이 통과했고, 나머지 4곡은 두 버전 모두 운지 미정 음 때문에 막혔다. 현재 코드로 내보낸 18곡은 alphaTab으로 다시 읽어 GP5·GP7 모두 첫 기타 트랙의 음표 다중집합이 일치했고, 모든 마디·성부의 음가 합이 마디 길이와 같았다.

해석할 때 주의할 점:

- 자동 정렬로 잰 값이라 절대 정확도가 아니며 버전 비교용이다. 악보가 녹음과 부분적으로 다르면(편곡 차이, 반복 생략) 두 버전 모두 낮게 나온다.
- 운지 비용 가중치와 첫 박 보정 설정은 같은 22곡으로 맞췄다. 한 연주자 곡으로만 맞추고 다른 연주자 곡에서 확인하면, 첫 박 보정은 양쪽 모두 좋아졌다(첫 박 F1 0.620→0.632, 0.540→0.556). 운지 가중치는 Kishibe 곡으로 맞추면 정성하 곡에서도 좋아졌지만(0.851→0.863), 정성하 곡으로 맞추면 Kishibe 곡에서 조정 전보다 조금 낮았다(0.933→0.926; 두 줄 정확도의 평균). 처음 보는 곡에서의 향상은 표보다 작을 수 있다.

남은 오류:

- 가장 큰 손실은 음표 인식(F1 61%)이다. 줄 정확도는 GAPS가 맞게 찾은 음에서만 잰다.
- 남은 운지 오류는 대부분 악보보다 낮은 포지션을 고른 경우다(사건의 지평선 528개 중 426개, Strawberry Moon 300개 중 271개). 두 곡의 줄 정확도(악보 음)는 71%, 75%다.
- Lemon은 비트 모델이 3박째를 첫 박으로 강하게 잡아 마디선이 반 마디 밀린다. WALTZ(6/8)는 8분음표를 박으로 잡아 3/4로 적고, 시대를 초월한 마음은 템포를 절반으로 잡는다.

## 남아 있는 품질 한계

**운지는 소리와 연주 가능성 규칙으로 추정한 값이다.** 같은 음높이를 여러 자리에서 낼 수 있어 연주자가 실제로 친 자리와 다를 수 있다. 영상의 손 위치로 이를 보정하던 기능은 측정에서 정확도를 높이지 못해 제거했다([알고리즘](algorithms.md) 6절). 튜닝·카포는 설명에서 읽거나 사용자가 채보 전에 입력한 값이며, 설명은 `Tuning:` 형식의 줄만 읽는다. 카포 변화와 변칙 튜닝을 소리나 영상으로 판별하지 못한다. 박자표와 마디 첫 박은 자동 추정이라 반 마디 밀림이나 6/8·3/4 혼동이 남아 있다. 특수 주법은 학습된 전문 분류기가 아닌 후보 규칙이다. 현재 결과는 손으로 다듬어 연습할 초안이고, 전체 악보 정확도나 수정 소요 시간을 보장하지 않는다.
