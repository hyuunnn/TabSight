# 검증과 한계

검증일: 2026-09-27. Apple Silicon Mac, Python 3.12, PyTorch MPS, Chrome에서 수행했다.

## GP·GP5 파일 검증

내보낸 GP·GP5 파일은 alphaTab의 독립 파서로 다시 읽어 **기타 음표 수와 음높이·줄·프렛의 전체 다중집합**이 내부 초안과 일치하는지 확인했다.

타악 후보는 별도 percussion 트랙으로 저장한다. 리듬은 64분음표 단위로 양자화되고 템포는 정수 BPM으로 저장되므로 파일 길이가 원본과 조금 다를 수 있다. 정확한 원본 시간은 프로젝트 JSON에 보존한다. 같은 줄의 재발음은 이전 음을 끝내며, 너무 가까운 같은 줄 음표를 파일에서 표현할 수 없으면 조용히 누락시키지 않고 보정을 요청한다.

특수 주법 후보가 다른 음의 줄을 차지해 음표가 사라지지 않도록 한다. 기존 운지와 양립하지 않는 하모닉스 후보는 운지를 강제로 이동하지 않고 `Harmonic?` 메모로 남긴다. 자연 하모닉스의 실제 음높이, 타이, 카포별 트랙, percussion 트랙은 별도 테스트로 확인했다.

Guitar Pro 데스크톱 프로그램에서 직접 열어 확인한 결과는 아니다. 반복 구조·복수 voice·고급 주법의 원본 악보 전체를 그대로 재현한다고 주장하지 않는다.

## 기능 검사

- Python 검사 **20개 통과**: 음높이 유지, 동시 현 중복 방지, GP/GP5 재읽기, 타이·재발음, 자연 하모닉스 음높이, 카포/타악 트랙, 미정·충돌 음표 차단, 저장 충돌, 실패 시 원본 유지, URL 검사, 취소, 기존 악보 표시, 설명·음역 충돌 처리, 프로젝트 삭제와 분석 중 삭제 거절, 설명의 음이름 튜닝·Nashville·다른 줄의 카포 읽기, 튜닝만 있는 설명의 카포 0 처리.
- 실제 Chrome 검사 **17개 통과**: 홈·실제 악보 표시, 악보 클릭 탐색, 원본 재생/배속, A–B 반복, 합성음, 수정/저장/되돌리기/다시 실행, 추가·삭제, 카포·튜닝 보정, 마디 템포, 새로고침 복원, 오선보 전환, GP5/GP 다운로드·재읽기, 모바일 레이아웃, 연습실 목록에서 삭제, 브라우저 예외 없음.
- 재생 표시 Chrome 검사(`npm run test:playback`) **8개 통과**: 실제 화면 픽셀 기준 재생선 너비, 먼 위치 탐색, 원음·악보음 재생 중 다음 줄 이동, 자동 넘김 해제와 위치 복귀, A–B 반복 시 이전 줄 복귀, 확대·오선보 전환 후 위치 유지, 모바일 한 마디 배치와 가로 넘침.
- TypeScript 검사와 Vite production build 통과.
- 영상 기능이 있던 이전 버전의 프로젝트 5개(데이터 복사본)를 현재 코드로 열어 확인했다. 남아 있는 `vision` 데이터는 무시되고, 나머지 필드와 음표는 그대로 읽히며, GP5 내보내기도 통과했다. 운지를 다시 계산하면 음높이는 유지되고 분석 당시 음성 기준 운지와 일치한다.

브라우저 검사는 분석이 끝난 프로젝트를 복제해서 사용하고 종료 후 복제본만 삭제한다. 결과 보고서와 스크린샷은 `test-results/`에 생성된다.

## 남아 있는 품질 한계

**운지는 소리와 연주 가능성 규칙으로 추정한 값이다.** 같은 음높이를 여러 자리에서 낼 수 있어 연주자가 실제로 친 자리와 다를 수 있다. 영상의 손 위치로 이를 보정하던 기능은 측정에서 정확도를 높이지 못해 제거했다([알고리즘](algorithms.md) 6절). 카포 변화와 변칙 튜닝 판별도 아직 충분하지 않다. 초기 박자는 4/4이며 음악적인 음가 정리가 필요하다. 특수 주법은 학습된 전문 분류기가 아닌 후보 규칙이다. 현재 결과는 손으로 다듬어 연습할 초안이고, 전체 악보 정확도나 수정 소요 시간을 보장하지 않는다.
